# boot tests

From the repository root:

```sh
bun run test packages/boot/test/proxy.test.ts
bun run test packages/boot/test/snapshots.test.ts
bun run test packages/boot/test/generations.test.ts
bun run test packages/boot/test/edit-lock.test.ts
bun run test packages/boot/test/source-files.test.ts
bun run test packages/boot/test/auth.test.ts
bun run test packages/boot/test/auth-http.test.ts
```

Vitest runs on Node; proxy and generation tests spawn real Bun boot/child processes and inspect actual SQLite files with an independent native client. Fixtures use native HTTP/process APIs deliberately. Tests cover health-gated routing, late health after exit, recovery availability, bounded/redacted stderr, guarded child access, shutdown, credentials, streaming, compression, and HTTP header semantics.

Generation tests cover relative imports and cwd reads from copied source, restart with broken/missing editable and seed trees, durable good tags/id reservation, bounded same-snapshot retries, schema migration, byte-identical newer-schema refusal, stored entry traversal, overlapping storage roots, and no reseeding after post-copy failure. Snapshot tests exercise nested copies, executable modes, exclusive concurrent reservation, source symlink rejection, and interrupted publication.

Edit-lock tests use independent Bun processes and real SQLite connections: competing owners, TTL and stale acquisition fencing, rejected-operation expiry cleanup, persisted create/replace/delete staging, pins and deferred break/revocation, explicit restart recovery, path rejection, and SIGKILL transaction rollback. Generation tests also cover schema 1–4 upgrades to schema 9, including preservation of auth/session records, active locks and staged deletions.

Server cutover tests now exercise authenticated editing, online backups and automatic restore. Production dependency immutability and OS ownership isolation remain untested.

Auth scenarios use signed software WebAuthn credentials with the real verifier and Bun SQLite. They cover setup rotation/recovery, concurrent first registration, RP/origin/UV/signature rejection, challenge expiry/replay, counters, atomic rollback on session insertion failure, hashed session storage, expiry/logout, and session reuse after a separate-process restart. The HTTP suite uses those signed credentials through real setup/login routes and checks cookie flags/redaction, replay, Origin enforcement, bounded/malformed bodies, verified identity forwarding, cookie replacement protection, logout, and authentication after all child retries fail. Transport/generation suites seed hashed sessions through test-owned SQLite, with no production authentication bypass. Browser interaction receives separate focused smoke validation rather than broad UI coverage.

Source-file tests use real Bun/SQLite and filesystem operations. A test-owned FileSystem adapter pauses committed-tree replacement at three boundaries; SIGKILL and a separate process prove recovery before the first replacement, between replacements, and after the final rename but before SQL completion. They also cover executable first-edit undo, snapshot isolation, journal independence from staging, idempotent replay, external bytes/mode conflicts, ancestor syncs, dangling/root symlinks, path collisions, stale/overlapping anchors, concurrent holder edits, pages without an app lock and large-file history exclusion. SQLite abort triggers model failed undo staging and failed history completion; those are injected storage faults, not physical disk exhaustion tests. Generation tests exercise startup recovery conflicts with live authentication/saved-good service and replay before interrupted-lock cleanup. No machine power-loss or Linux ownership guarantee is claimed by these local tests.

`events.test.ts` adds migration from schema v5 to the current schema with exact pending source bytes/modes, staging and session preservation; delayed publication behind a higher boot event; exact-range rejection; cross-attempt duplicate validation; no resurrection after pruning; committed versus absent app evidence; the fence-committed/reservation-unresolved crash state; inconsistent-evidence fencing; and missing initialized-store refusal. Server integration tests separately exercise actual HTTP messages, kernel commit/relay crash points, guarded attempt rotation and an orphaned process's SQLite write gate. Tests of the internal append/write services do not by themselves establish request/generation event emission through the running bootloader.

`enrollment.test.ts` uses signed proof fixtures and separate Bun/SQLite processes for action/id/grant/lifetime binding, cross-ceremony/replay/UV/RP/origin/counter/expiry rejection, concurrent proof and collection, semantic refusal consumption, approval-event rollback, half-pair insertion rollback, hash-only storage, and collection/access persistence after restart. The v6-to-v7 migration test compares prior passkeys, sessions, challenges, active lock/staging/source journal bytes, pending reservations and batch receipts exactly. Server enrollment HTTP tests cover the real router/proxy and two-agent conversation. Chrome virtual-passkey approval receives a narrow manual smoke rather than a UI test framework.

`tokens.test.ts` exercises exact concurrent refresh replay, fixed grace and expiry boundaries, successor chains/use evidence, family-scoped idempotency conflicts, 24h/30d and 7d/90d grants, authenticated-receipt corruption/hash checks, transactional insert/event faults, signed human revocation, lock pins, unknown-family proof consumption and schema-v7 credential preservation. Separate Bun processes replay a persisted pair; SIGKILL before outer transaction commit proves rollback, and after commit before response proves exact receipt recovery. Test-owned wrappers place these crash boundaries; production has no fault injection hook. Server token HTTP tests cover aliases, bearer scope-refusal use, event-publication gaps, process restart, and logout/expiry while a signed revocation body is held. The held-body assertion also checks proof consumption, proving it reached the transaction after initial session admission.

`child-keeper.test.ts` verifies natural app exit with the parent pipe still open, EOF cleanup of signal-resistant and event-loop-hung children, SIGTERM cleanup, and absence of a closure receipt after keeper SIGKILL. `app-backup.test.ts` verifies restore after handles close and distinguishes an uninitialized clone from corrupt initialized schema. Server health tests additionally prove the newest committed message exists only in WAL before online cloning. Server cutover tests cover continuous acknowledged writes through good/bad/good edits, candidate-only destructive migration rollback, actual boot SIGKILL before and after acceptance, unavailable-app repair, held-body admission/drain and queued logout reauthentication. Physical disk exhaustion, machine restart closure proof, backup/snapshot retention and OS isolation remain separate work.

`event-retention.test.ts` covers exact age boundaries, unpublished rows, persisted settings, invalid-policy refusal and next-hour retry, interruption, bounded chunk commits with SQL fault rollback, separate-process resumption, durable batch receipts, replay without resurrection and sequence gaps. Retention does not prune app outbox/idempotency evidence or allocator state. These tests do not prove physical disk reclamation or byte-budget enforcement.

Account management tests cover human-only secret-free enrollment/family listings, direct grants without enrollment, signed additional-passkey registration and serialized last-key protection. Passkey tests exercise actual registration completion across process restart, changed registration/session/action bindings, stale and deleted authorizers, SQL rollback, and logout during a held request. Mint tests exercise exact concurrent/restarted response replay, session-scoped encryption, request/proof conflicts, receipt corruption, family revocation, both duration modes, and real SIGKILL before/after commit. Synthetic legacy migrations remove the new receipt table before replaying schema v11 and preserve prior credentials, source state and session presence. The management UI is not part of these API tests.

`backup-metadata.test.ts` upgrades a legacy v11 backup without guessing its missing fence/generation. Scheduled backup tests cover admitted-write drain and authoritative publication reconciliation, successful same-epoch capture, failed freeze recovery, missing closure proof and clone/catalog failure cleanup. Server maintenance process tests exercise the actual scheduler, scratch rehearsal, durable attempts across restart, live-data preservation and failure isolation. Physical disk budgets and user-selected database restore remain separate acceptance work.
